## When to use this

Begins on Go-Live day; ends when exit criteria are met. Evidence for
[B.4.2 Post-deployment Documentation](../../../module-b/4-2-post-deployment-documentation/).

<Aside type="tip">
  The exit criteria — not the duration — define when hypercare ends. A
  fixed-date hypercare with no exit criteria is a common audit gap.
</Aside>

## Plan structure

### 1. Scope and duration

- Hypercare covers the production AVD service from Go-Live to exit criteria
  being met
- Target duration: 2–4 weeks
- Coverage hours: e.g. business hours + on-call for P1 / P2 outside hours

### 2. Communication channels

| Channel | Purpose | Audience |
|---|---|---|
| Teams channel "AVD Hypercare" | Live triage, day-to-day | Customer ops + partner team |
| Email DL hypercare@... | Async follow-ups, ticket links | Same |
| On-call rota | P1 / P2 out of hours | Customer-nominated on-call + partner on-call |
| Daily stand-up (15 min) | Open incidents, planned changes | Both sides |
| Weekly review (60 min) | Trends, exit criteria progress | Customer ops manager + partner engagement lead |

### 3. Escalation matrix

| Severity | Definition | Response time | Owner |
|---|---|---|---|
| P1 | Service down or many users impacted | 15 min | Partner on-call → customer ops manager |
| P2 | Significant degradation for a subset | 1 hour | Partner engagement lead |
| P3 | Single user / minor issue | Next business day | Service desk → partner if escalated |
| P4 | Enhancement / question | Weekly review | Engagement lead |

### 4. Daily cadence

- 09:00 stand-up (15 min): open issues, planned changes, blockers
- Open ticket review in Teams channel
- On-call handover at end of day

### 5. Weekly cadence

- Incident trends (count by category, by severity)
- Open vs closed
- AVD Insights review (logon perf, connection failures, host load)
- Cost actual vs forecast
- Exit criteria progress

### 6. Exit criteria

Hypercare ends when **all** of these are true:

| Criterion | Threshold |
|---|---|
| All P1 incidents resolved | Yes |
| All P2 incidents resolved | Yes |
| Total incident rate | &lt; 1 per user per week (rolling 7d) |
| Logon time P95 | Within HLD target |
| Customer ops team confidence | Self-assessed ≥ 4/5 |
| Runbook validated against real incidents | Yes |
| Open P3 backlog | &lt; agreed threshold |

### 7. Exit sign-off

| Role | Name | Date | Signature |
|---|---|---|---|
| Customer ops manager | | | |
| Customer EUC lead | | | |
| Partner engagement lead | | | |

### 8. Post-hypercare arrangements

- Steady-state support contract (separate)
- Lessons learned filed against this repo (innersource)
- Next WAF re-assessment scheduled
