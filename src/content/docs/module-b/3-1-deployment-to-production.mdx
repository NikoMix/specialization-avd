## What the Auditor Checks

The auditor verifies that the AVD workload was **deployed to production**
following the design, using IaC, and that **Go-Live** is recorded with a
configuration baseline.

**Typical questions:**
- Show me the production pipeline run that deployed AVD.
- What is the configuration baseline at Go-Live?
- When did production go live and who signed off?

---

## Required Evidence Checklist

| # | Evidence Item | Accepted Formats | Status |
|---|---|---|---|
| 1 | **Production IaC pipeline run** that deployed / promoted AVD | Screenshot, PDF, pipeline export | ⬜ |
| 2 | **Configuration baseline** at Go-Live — host pool config, session host SKU + count, image version, FSLogix config, scaling plan | PDF, Excel | ⬜ |
| 3 | **Go-Live record** — date, scope, attendees, sign-off | PDF, Word, Email | ⬜ |
| 4 | **Cutover plan** (for migrations) — RDS / Citrix / Horizon retirement steps, rollback plan | PDF, Word | ⬜ |
| 5 | **Change records / change advisory board** approvals if applicable | PDF, ITSM export | ⬜ |
| 6 | **Customer sign-off** on Go-Live | PDF, Word, Email | ⬜ |

<Aside type="tip">
  Per the V2.7.1 glossary, "Go-Live" means production workload serving end
  users. Hosting infrastructure deployed but not yet serving users does NOT
  count.
</Aside>

## Evidence Guidance

### Configuration baseline template

| Component | Value at Go-Live |
|---|---|
| Host pool name & type | `hp-prod-knowledge` / Pooled |
| Load balancing algorithm | Breadth-first |
| Max session limit | 8 per host |
| Session host SKU | D8as v5 |
| Session host count | 100 (autoscaled, baseline 20) |
| Image version | `gold-w11-23H2-2025-11` |
| FSLogix profile share | `\\stavdprod.file.core.windows.net\profiles` (Azure Files Premium) |
| FSLogix Office container split | Enabled |
| Scaling plan | `sp-prod-knowledge` (working hours 07:00–19:00 UTC+0) |
| RDP Shortpath | Enabled (managed network) |
| Identity | Entra-joined + Intune |
| MFA | Enforced via CA `CA-AVD-MFA-Compliant` |

### Go-Live record

- Date (in UTC and customer local time)
- Scope (which users, which apps, which sites)
- Attendees from customer side (named, role)
- Final pre-Go-Live checks passed (link to B.4.1 test results)
- Sign-off (named customer sponsor + your engagement lead)

### Cutover (migrations)

For RDS / Citrix / Horizon migrations:

- Cutover wave schedule
- Source-system retirement steps (when to stop accepting new users, when to
  shut down)
- Rollback plan (how to send users back to the source system if AVD has
  a critical issue inside the cutover window)

## Common Gaps

| Gap | Remediation |
|---|---|
| Production was click-deployed, not via IaC | Show that subsequent material changes have moved to IaC; document the transition |
| Configuration baseline never captured | Capture the current state and back-date with change-log evidence |
| No formal Go-Live record | Create one retrospectively with the customer sign-off — better than nothing |
| Cutover lacked rollback plan | Document the rollback retrospectively; bake into the runbook for next time |
